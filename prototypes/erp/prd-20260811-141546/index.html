平台仓库映射与换货处理规则

统一维护店铺后台仓库与系统仓库的映射，以及订单换货判定与 SKU 替换方案。

版本V0.4状态评审中日期2026-08-11
本期范围：仅包含平台仓库映射规则、换货处理规则；不包含其他订单规则。

1. 背景与范围

同一实体仓库在不同店铺下可能有不同平台仓库编码，需要按平台、店铺和后台仓库编码定位系统仓库。换货流程则需要把“哪些订单换货”和“换成哪些 SKU”合并为一条可执行规则。

类别说明
目标两类规则在同一“规则配置”入口完成查询、新增、编辑和启停，新增配置无需修改代码。
包含仓库唯一映射；换货 AND/OR 条件组；人工/自动审单；命中 SKU/全部 SKU 两种替换范围；规则快照。
不包含换货 SKU 库存校验、缺货兜底、三层条件嵌套、历史订单重新计算、批量导入。
兼容要求原测评订单换货拦截流程迁移后默认使用“人工审单”，不得改变原有操作结果。

2. 用户与场景

用户/系统任务典型场景
规则管理员创建、编辑、启停和检查两类规则。新店铺或仓库上线；换货策略调整。
订单运营人员处理人工审单换货订单，填写测评费用并转待发货。测评订单命中后由用户确认，再触发 SKU 替换。
订单处理服务读取启用配置，保存命中快照并执行仓库映射或换货。新订单进入 ERP 时自动处理。
仓库示例：TIKTOK_08_us 的“顺友美东仓”编码为 7654839757679560449，映射到 ERP 系统仓库“顺友美东仓”。其他店铺使用同一实体仓，也需单独维护自己的编码。

3. 业务流程

flowchart TD
  A[新订单进入 ERP] --> B{需要仓库映射}
  B -->|是| C{找到唯一启用映射}
  C -->|否| D[阻断订单并报错]
  C -->|是| E[写入系统仓库]
  B -->|否| F[按优先级匹配换货规则]
  E --> F
  F --> G{任一条件组成立}
  G -->|否| H[继续正常流程]
  G -->|是| I[保存快照并停止匹配]
  I --> J{审单方式}
  J -->|人工| K[停留待审核]
  K --> L[用户填费用并转待发货]
  J -->|自动| M[系统自动通过审核]
  L --> N[按快照替换 SKU]
  M --> N
  N --> O[进入待发货]
  • 配置新增、修改和停用只影响后续新订单。
  • 订单命中时保存规则快照，后续配置变化不影响已命中订单。
  • 系统只执行一次 SKU 替换；用户后续修改时以用户结果为准。

4. 功能需求

4.1 公共交互

  • 页面仅保留“平台仓库映射规则”和“换货处理规则”两个标签。
  • 切换标签时同步切换筛选器、列表字段和新增按钮；不展示固定说明提示框。
  • 新增、编辑使用右侧抽屉；保存成功后关闭抽屉并刷新列表。
  • 换货判定与 SKU 替换在同一条规则、同一编辑抽屉中维护，不再拆分标签或列表。
  • 新增、编辑、启用、停用、删除分别配置按钮权限；无权限时不展示对应按钮。

4.2 平台仓库映射规则

模块字段/功能规则
筛选平台、店铺、后台仓库名称、系统仓库名称平台与店铺联动；查询后返回同时满足条件的数据。
列表平台/站点、店铺、后台仓库、后台仓库编码、系统仓库、状态、更新信息、操作系统仓库同时展示名称与 ID；本期提供编辑和启停。
编辑字段平台、店铺、站点、后台仓库名称、后台仓库编码、系统仓库、状态、备注除备注外必填；系统仓库从主数据选择并带出 ID；新增默认启用。
唯一键平台 + 店铺 + 后台仓库编码编码按字符串保存；重复配置时阻止提交。
执行新订单按唯一键匹配启用映射匹配成功写入系统仓库；未匹配时订单直接报错，不使用默认仓库兜底，也不在规则配置模块增加异常处理功能。

4.3 换货处理规则

模块字段/功能规则
筛选规则名称、审单方式、平台、状态审单方式包括全部、人工审单、自动审单。
列表规则类型、名称、详情、优先级、状态、执行次数、创建信息、更新信息、操作命中条件和替换方案只在编辑抽屉查看；支持编辑、删除、启停。
基础信息名称、优先级、状态、平台、店铺、站点、备注优先级为 1—999999 的正整数，数值越大越优先；新增默认启用。
条件组合条件字段、操作符、条件值组内 AND、组间 OR；至少 1 组，每组至少 1 条完整条件。
审单方式人工审单 / 自动审单人工：待审核后由用户转待发货；自动：系统自动通过审核。
替换范围只替换命中的 SKU / 替换全部发货 SKU选择“只替换命中”时，条件中必须存在平台 SKU 或发货 SKU。
替换方案原 SKU、换货 SKU、固定数量按“原 SKU → 换货 SKU”逐项一一对应，至少 1 条；同一原 SKU 不可重复配置，数量为大于 0 的整数，默认 1；本期不校验库存。
规则生效优先级匹配、规则快照优先级从高到低；相同优先级按最后更新时间最新的一条执行；命中一条后停止匹配后续换货规则。编辑或停用只影响新命中订单。
条件字段：沿用现有换货拦截能力，以枚举形式提供系统 SKU、订单金额、订单商品数量、平台运输方式、分仓仓库、利润/利润率、平台 SKU、item_id、订单类型、物流渠道、location、包裹重量、SKU 销售状态、是否有 SKU 留言、发货 SKU 等。操作符及条件值控件按字段类型联动，不允许手输字段名。

4.4 核心验收标准

编号场景预期结果
AC-01保存重复仓库唯一键阻止保存并提示映射已存在。
AC-02新订单无仓库映射阻断订单并报错，不自动选择其他仓库。
AC-03条件组为“（A AND B）OR C”A、B 同时满足或 C 满足时命中。
AC-04人工/自动审单规则命中分别按人工等待操作、系统自动通过的流程完成 SKU 替换。
AC-05只替换命中 SKU，但无 SKU 条件阻止保存并定位提示到条件区域。
AC-06多条换货规则同时满足先按优先级降序；同优先级执行最后更新时间最新的一条；首条命中后停止匹配。
AC-07命中后规则被修改，或用户修改已替换 SKU订单使用命中快照；用户后续修改不被系统覆盖。

补充决策

事项已确认口径
换货规则冲突相同优先级执行最后更新时间最新的一条；命中一条后停止匹配后续规则。
多 SKU 关系原 SKU 与换货 SKU 必须逐项一一对应。
仓库映射失败订单直接报错；规则配置模块不增加异常调整或重试功能。
操作权限新增、编辑、启用、停用、删除采用按钮级权限控制。
