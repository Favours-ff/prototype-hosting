需要组合调用的场景

Shopee · 加价购与满额赠

拉附加交易列表→取活动 ID 和规则→分别拉主商品和附加商品

用 add_on_deal_id 关联。商品保留主商品、加购商品或赠品的角色。

TikTok Shop · 活动与优惠券

分别拉活动、券→读取各自的分页游标→用各自的 ID 查详情

活动的 page_token 放请求体，优惠券的 page_token 放 Query。

Lazada · Flexicombo

列表取活动 ID→详情取规则和赠品→指定商品逐页拉全

同一活动可以同时提供折扣和赠品。按同一个活动 ID 入库，保留两类规则。

一平台一张表怎么存

四类数据共用列，规则和参与商品保存为 JSON。

每张表的唯一键　站点 + 店铺 + 来源模块 + 平台优惠 ID

数据落库内容
活动与券的基础列保留来源模块、平台活动 ID、名称、原始类型、原始状态、ERP 类型、适用范围、起止时间、币种、最近同步时间。原始类型和 ERP 类型各自保存，ERP 类型支持多值。
规则 JSON存门槛、优惠值、限额、档位、领取及使用条件。金额按原币定点存储，优惠百分比按来源字段定义转换。
商品 JSON存商品 ID、规格 ID、主商品/加购/赠品角色、对应档位、活动价、活动库存和限购数量。全店适用单独记录范围，商品清单可为空。
原始回包与同步状态保留接口版本、原始回包或引用、同步时间和完整性。详情或商品页失败时，保留上次完整明细，失败的部分进入补拉。
Lazada SKU 特价需要从现有 Listing 补入时，来源模块标为商品特价，记录键使用 item_id + sku_id。Flexicombo 仍按其活动 ID 存一条。

联调核对

  • 店铺授权。 Shopee 传 partner_id、shop_id、access_token、秒级 timestamp 和 sign。TikTok Shop 传 shop_cipher、app_key、秒级 timestamp 和 sign，令牌放 x-tts-access-token。Lazada 按站点网关传 app_key、access_token、毫秒级 timestamp、sign_method 和 sign。
  • 分页和更新。 各按接口的 more、next_page_token 或分页总数收齐。支持更新时间过滤时按窗口拉，其他接口定期分页重扫。整批成功后再推进同步进度。
  • 数值与时间。 活动、商品、SKU ID 按字符串保存。TikTok Shop 活动起止为秒，创建/更新时间为毫秒。Lazada 以接口单位和站点后台核对，例如店铺闪购样例的日期字符串没有时区。
  • 店铺验收。 每个平台用一个已授权目标店铺，核对一张全店券、一张指定商品券和一条有 SKU 明细的活动。TikTok Shop 直播、达人秒杀覆盖，以及 Lazada Flexicombo 商品列表返回 ID 的粒度，分别用店铺非空样本核实。记录业务错误码和 request_id。
