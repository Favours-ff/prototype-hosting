巴西 TikTok Shop 自动开票全流程

一张 NF-e 对应一个待上传发票的 package；Focus 授权与 TikTok 验票是两次独立异步流程

开票唯一键

ref = BR_{shop_id}_{package_id}。同一张票的网络重试、Focus 处理中查询都复用同一 ref；只有税局已明确拒绝并修正数据后，才创建新的开票任务和新 ref。

Focus 企业档案自动带出

公司名称、地址、税制、A1 证书。ERP 按店铺映射选中对应 Focus 主体，并调用对应的生产 Token；Token 仅后端加密保存，不能返回前端。

ERP 每票传入 / 组装

开票 CNPJ、IE、买家 CPF/姓名/地址、商品明细、金额、税务编码、支付方式；中介 CNPJ 与开票 CNPJ按已确认规则同源取值。

两条消息回调

Focus 授权结果回调与 TikTok 事件 36 回调都需要 ERP 对外提供 HTTPS Webhook URL；同时保留定时查询作为漏消息补偿。

PRD 业务规则与订单列表展示

面向所有 TikTok 巴西店铺；前台仅展示三种开票状态

开票触发

订单所属店铺为 TikTok 巴西店铺，且订单详情中包裹的 need_upload_invoice=NEED_INVOICE，并且该订单已完成盈亏计算时，系统创建开票任务。

前台状态只有 3 种

待开票：已满足触发条件，尚未提交 Focus；开票中：已提交 Focus，至 TikTok 验票完成前；开票失败：任一环节终止失败，等待人工处理。

开票成功如何展示

不新增“开票成功”状态。验票成功后，订单列表取消状态标签，改展示 NF-e access key、发票号、XML/PDF 下载入口、TikTok 验票成功时间。

待确认：取消订单

NF-e 已授权后客户取消、退款或退货时，需巴西会计确认使用“取消 NF-e”还是“退货 NF-e”；确认前不自动处理原票。

触发与基础数据利润未计算；CPF/姓名/地址缺失或脱敏；包裹信息缺失；订单取消。开票失败 + 原始异常信息补齐或确认订单数据后，重新发起开票任务。

Focus 同步校验HTTP 400/401/422；必填参数、格式、企业档案或证书问题；同 ref 已有终态记录。开票失败 + Focus 返回 code/message修正后处理；网络超时或处理中时，先查询原 ref，不直接新开票。

TikTok 上传与验票上传接口错误；事件 36 返回 FAILED/INVALID；NOT_FOUND、NOT_AUTHORIZED、ACCESS_KEY_DUPLICATE、CNPJ_NOT_MATCH、UF 不一致。开票失败 + TikTok invalid_reason / request_id按原因处理；NOT_FOUND 可等待同步后重传同 XML；重复 access key 先核查原上传记录。
消息通知Focus/TikTok webhook 未配置、回调失败、重复回调或未收到事件。开票中 + 回调异常信息定时查询 Focus；核查 TikTok webhook 配置并人工对账处理。

NF-e 开票信息

红色星号仅为 Focus 接口 required；其他标签说明业务处理要求。

Focus NF-e 4.00

接口必填

ref、natureza_operacao、data_emissao、tipo_documento、finalidade_emissao、items。这些缺失时，Focus 直接拒绝请求。

业务必填

店铺对应开票主体、买家 CPF 与可开票地址、SKU 税务模板、数量/金额/折扣映射。接口未全部标 required，但没有这些数据无法合规开具本业务 NF-e。

条件必填

已固定 indicador_intermediario=1，因此中介 CNPJ 与商家登记号必须传；中介 CNPJ 按本业务规则复用店铺开票 CNPJ。

接口可选

local_destino、consumidor_final、presenca_comprador、运费/支付字段可不传；表单保留店铺业务默认值。

发票、店铺与 Marketplace
