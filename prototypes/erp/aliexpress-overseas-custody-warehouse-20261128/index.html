速卖通海外托管订单自动匹配系统仓（OMS 订单侧调整）

日期：2026-11-28 ｜ 改动范围：仅改 OMS 后端订单匹配，仓库管理页面不动、不接新接口

一、背景与改造范围

  • 现状（实测）：速卖通海外托管平台仓发单同步时未解析平台仓编码，包裹全部落入 AEBTGYXC（AE半托管优选仓）（例：订单 3077973286952446 实际应落 AE平台仓波兰1仓）。
  • 本次改动：「仓库管理」页面完全不改，只在 OMS 订单解析/生包环节，拿订单里的平台仓编码先查库存表映射出仓名称，再去物流系统「仓库管理」匹配对应系统仓。

二、订单匹配逻辑（两步查表）

  1. 命中条件（3 项同时满足）：
    • 店铺满足 data_center_db.shop_auth.is_overseas_custody = 1；
    • 子单 send_goods_operator = 'WAREHOUSE_SEND_GOODS'；
    • 子单 logistics_warehouse_type = 'cainiaoInternationalWarehouse'。
    隔离说明：海托店自发货单（SELLER_SEND_GOODS、wc = ae_marketplace）与普通半托管/全托管国内优选仓订单保持原逻辑不变。
  2. 取订单平台仓编码：从 order_db.aliexpress_order_raw_data_details.child_order_list 子单 extend_map（JSON 字符串二次解析）取 wc（去首尾空格，如 AEPL001）。
  3. 第一步：查平台仓编码 → 仓名称映射表：
    • 查现成表 data_center_db.aliexpress_warehouse_inventory，条件 ware_code = wc AND is_del = 0，取对应的 ware_name（例：AEPL001 → AE平台仓波兰1仓）。
  4. 第二步：匹配物流系统「仓库管理」列表（logistics_db.warehouse）：
    • 固定范围：platform_en = 'AliExpress' AND ecang_warehouse_type = 15 AND ecang_warehouse_status = 1 AND is_del = 0（不强卡 shop_id 数组，避免新开海托店漏勾店铺）。
    • 匹配顺序：
      1. 用第一步查出的 ware_name 匹配 logistics_db.warehouse.warehouse_name（仓库名称）；
      2. 若第一步未查到或名称未命中，兜底用 wc 匹配 overseas_ware_code（海外仓编码）或 warehouse_code（仓库编码）。
    • 命中唯一启用仓后写入订单及包裹，不再落入 AEBTGYXC；若命中多个启用仓则报异常提示存在重复配置。
  5. 异常处理与幂等保护：
    • wc 为空、解析失败，或两步查表均未命中启用系统仓：禁止兜底落入 AEBTGYXC，订单打异常并展示缺失的 wc（与 ware_name）；运营在仓库管理补建/启用后重跑检测即可匹配。
    • 同单多子单 wc 不一致时按子单拆仓，不支持拆仓则转异常并列出各 wc，不静默覆盖。
    • 已有有效未作废包裹、已交运/已发货或人工改仓后的订单，后续同步不覆盖发货仓；上线前历史已发货订单不回刷。

四、验收要点

  • 海托仓发单（3077973286952446、3078315080769460 及未付款单 3078540629843334）经两步查表精准匹配至波兰1仓 / 波兰2仓 / 法国1仓，不再落入 AEBTGYXC。
  • 未知 wc（如 AEDE001）或对应系统仓已停用时，订单打异常并提示具体 wc，不兜底优选仓；补建/启用后重跑检测恢复。
  • 海托自发货单（wc = ae_marketplace）与普通半托管优选仓单不受影响；已生包/已改仓单重复拉单不覆盖。
