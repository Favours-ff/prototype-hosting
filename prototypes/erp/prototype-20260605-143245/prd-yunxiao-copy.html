速卖通全托管商品管理与库存同步 PRD

版本：V1.2 · 产品范围：全托管商品只读管理 + SKU 多仓库存维护 + 库存同步规则 · 更新日期：2026-09-01

1. 项目背景

自研 ERP 需要统一拉取并展示速卖通全托管店铺的 Listing、SKU、审核状态、供货价、平台多仓库存、本地库存和货品绑定信息。考虑卖家 Listing 数量可达到十万级，列表以 Listing 为主体，不在主列表内展开 SKU；SKU 通过右侧抽屉集中查看和维护。

本期同时接入库存同步能力，允许用户按 SKU 独立启停库存同步并配置补货方式，系统后台按 SKU、平台仓库计算目标库存并执行同步。

核心边界：商品标题、价格、审核状态、上下架等商品信息仅拉取和展示；页面不提供商品编辑、发布、调价和上下架操作。可修改范围仅包括 SKU 平台仓库存数量及库存同步规则。

2. 产品目标与范围

类型内容
产品目标完整展示全托管 Listing 与 SKU 数据；支持多维筛选、状态切换、日志追溯、多仓库存维护及库存同步规则配置。
本期范围全托管店铺识别、商品列表与详情同步、Listing 状态统计、SKU 抽屉、在线 SKU 与本地 SKU 关系、多仓库存、本地可用库存、活动标识、操作日志、SKU 库存同步开关及三类补货规则。
不在本期商品发布、商品详情页、标题编辑、供货价调整、采购价调整、商品上下架、审核状态修改、货品绑定编辑、原始 JSON 查看。

3. 用户角色与使用场景

角色核心场景权限
运营按店铺、类目和状态查看商品；查看审核原因和 SKU；维护各平台仓库存；配置库存同步规则。查看、筛选、导出、维护库存、配置规则、查看日志。
系统任务定时同步商品、SKU 与仓库库存；执行已开启的库存同步规则；回查平台结果。调用平台查询与库存更新接口，写入同步日志。
研发 / 支持根据商品、SKU、仓库和任务标识排查同步异常。查看操作日志和接口日志。

4. 页面信息架构

  1. 页面标题区：展示“速卖通全托管商品”及业务说明，不展示左侧菜单。
  2. 筛选区：高频筛选默认展示，低频筛选通过“展开更多筛选”显示；同一行控件等宽对齐。
  3. 状态 Tab：仅展示全部、销售中、审核中、审核不通过、已下架。
  4. 商品列表：以 Listing 为分页单位，默认每页 100 条，支持切换 50、100、200、500 条/页。
  5. SKU 明细：点击商品信息中的“SKU N 个”入口，从右向左打开宽抽屉，不在列表内展开。
  6. 操作日志：列表操作列仅保留“日志”，弹窗支持时间、操作模块和操作人筛选。
  7. 库存同步规则：勾选 Listing 后打开弹窗，按所选 Listing 下的 SKU 配置。

5. 商品筛选与排序

筛选项控件枚举 / 规则
商品关键词类型下拉 + 输入框商品 ID、商品标题、SKU 编码。
货品关键词类型下拉 + 输入框货品 ID、货品条码、本地 SKU。
全托管店铺下拉展示 ERP 店铺名称，如 SMT01全托管；筛选项和列表同时展示运营负责人。
类目级联选择器按一级、二级、三级类目逐层选择；以类目名称筛选，不展示类目 ID。
备货类型下拉JIT 即时补货、仓发、国内履约、海外仓。
库存状态下拉有库存、库存为 0。
货品绑定下拉全部已绑定、部分绑定中、未绑定、解绑拒绝。
活动状态下拉全部活动状态、参加活动、未参加活动。
排序下拉创建时间倒序、创建时间正序、30 天销量从大到小、30 天销量从小到大。

6. 状态统计逻辑

6.1 主状态

Listing 主状态互斥，一个 Listing 同一时间只能属于一个主状态：

全部 Listing = 销售中 + 审核中 + 审核不通过 + 已下架
状态统计单位判断规则
全部Listing当前公共筛选范围内去重后的全部有效 Listing。
销售中Listing平台商品状态正常在线，且最新审核结果已通过。
审核中Listing已提交平台审核，尚未产生最终审核结果。
审核不通过Listing最新一次有效审核结果为不通过。
已下架Listing商品状态命中平台下架、删除或失效状态。

6.2 特征统计

售罄和货品未绑定属于可重叠特征，不作为状态 Tab。页面汇总区域可继续展示“售罄 SKU”和“货品未绑定”数量。

  • 售罄 SKU：该 SKU 所有有效平台仓库库存合计小于或等于 0。
  • 部分仓缺货：至少一个仓库库存为 0，但 SKU 所有仓库库存合计大于 0。
  • 货品未绑定：SKU 不存在有效本地 SKU 绑定关系。
状态注意：库存为 0 只能判断售罄，不能判断商品下架；单次列表接口未返回商品也不能直接判断下架。

7. 商品列表字段

字段展示规则
商品主图、标题、活动 SALE 标签、商品 ID、一键复制、类目名称、SKU 数量及 SKU 风险摘要。标题和类目超长时省略，悬浮展示完整内容。
店铺店铺名称和运营负责人独立展示。
备货类型展示 JIT 即时补货、仓发等类型。
审核状态销售中 展示“处于正常销售状态”；审核中 展示“等待平台审核中”；审核不通过 展示中文具体原因，悬浮显示完整内容。
商品状态展示平台商品当前状态的中文名称，例如“在线”“待审核”“审核驳回”；不展示英文状态码，并与审核状态分列展示。
供货价 / 采购价单 SKU 显示单价；多 SKU 价格不同时显示最低价至最高价区间；下方展示 ERP 系统采购价。
库存并排展示平台在售库存合计与本地可用库存。
近 30 天销量展示销量及环比变化。
货品绑定展示 Listing 下 SKU 的绑定汇总。
时间同一列分两行展示“后台创建”和“系统更新”：后台创建为 Item 在平台后台的创建时间，也是列表创建时间排序依据；系统更新为 ERP 最近一次成功更新该 Item 数据的时间。统一格式为 YYYY-MM-DD HH:mm:ss。
操作仅保留日志按钮，不展示详情、JSON 和独立 SKU 按钮。

8. SKU 明细抽屉

8.1 进入与布局

  • 点击商品信息下方“SKU N 个”打开右侧宽抽屉。
  • 抽屉宽度应保证常用桌面分辨率下无需横向拖拽；SKU 数量较多时仅列表区域垂直滚动。
  • SKU 表头吸顶，垂直滚动时字段名称保持可见。
  • 抽屉展示该 Listing 下全部 SKU，不限制只展示前三条。
  • 每个 SKU 展示自己的封面图片。

8.2 商品头部

展示商品主图、标题、商品 ID、店铺、运营和类目。字段使用独立信息块或间距分隔，不使用连续圆点。Listing 参加活动时仅在商品标题旁展示 SALE 标签；鼠标悬浮显示“商品正在参与平台活动”。

8.3 SKU 字段

字段要求
SKU 信息SKU 名称、在线 SKU、本地 SKU、SKU 编码、货品条码、货品 ID；货品 ID 固定完整换行展示，不截断。
规格颜色、尺寸等变体属性。
销售状态销售中、停售等。
供货价该 SKU 的平台供货价。
多仓库存分别展示每个平台仓库名称、仓库编码和当前库存输入框。
本地可用本地仓库编码和本地可用库存，作为平台库存维护和同步规则参考。
货品绑定绑定中、已绑定、未绑定等。
补货方式展示当前 SKU 已配置的库存补货方式。

9. 多仓库存维护

全托管店铺支持多个平台仓库，同一个 SKU 可以在不同仓库拥有独立库存。例如：

SKU A
├─ 东莞仓：10
└─ 杭州仓：20

平台总在售库存 = 10 + 20 = 30
  1. 库存读取和保存的最小粒度为“店铺 + Listing + SKU + 平台仓库”。
  2. 用户可以分别修改不同平台仓库的库存数量。
  3. 保存时仅提交发生变化的仓库库存。
  4. 保存成功后回查平台库存，并更新 Listing 平台库存合计。
  5. 每次修改记录旧库存、新库存、SKU、仓库、操作人和平台返回结果。
活动库存保护：Listing 参加平台活动时，各 SKU、各仓库的目标库存只能保持或增加，不能低于该仓库当前平台库存。校验必须按仓库分别执行，不能只比较仓库库存合计。

10. 操作日志

商品列表操作列仅提供“日志”入口，点击后打开操作日志弹窗。

筛选项规则
操作时间使用一个时间范围输入框；点击后打开日历面板，选择开始日期和结束日期。
操作模块全部模块、商品同步、库存同步、货品绑定、审核状态、库存同步规则、商品列表同步。
操作人全部操作人、具体运营人员、系统任务。

日志列表字段：操作时间、操作模块、操作内容、操作人。默认每页 10 条，支持切换每页条数、页码和跳页。

11. 库存同步规则弹窗

11.1 进入方式

  1. 用户在商品列表勾选一个或多个 Listing。
  2. “库存同步规则”按钮变为可点击。
  3. 点击后展开所选 Listing 下的全部 SKU。

11.2 顶部筛选

筛选项枚举
映射关系全部、已映射、未映射。
同步状态全部、开启、关闭。
补货方式全部、本地可用库存、自定义数量、无库存兜底。

11.3 SKU 表格

字段说明
选择框每条 SKU 独立勾选；表头支持全选，用于批量修改补货方式。
SKU 信息SKU 名称、在线 SKU、本地 SKU、店铺，全部左对齐。
可售数量平台当前可售库存。
本地可用ERP 本地 SKU 可用库存。
库存同步每个 SKU 独立开关。开启后后台任务执行规则；关闭后保留配置但不执行。开关状态必须持久化。
补货方式每个 SKU 独立选择。
补货逻辑根据补货方式显示对应阈值、数量和计算说明。

11.4 单独修改与批量修改

  • 逐条修改：直接修改某一 SKU 的库存同步开关、补货方式和补货参数。
  • 批量修改：勾选多条 SKU 后，在顶部选择补货方式并应用到已选 SKU。
  • 批量修改只覆盖已勾选 SKU，不影响未勾选 SKU。
  • 批量应用后，用户仍可以继续单独修改某条 SKU。

12. 库存同步规则

补货方式触发与计算逻辑说明
本地可用库存target_qty = local_available_qty本地仓库 SKU 有多少可用库存，平台目标库存同步为多少。
自定义数量平台在线库存低于阈值时，补到指定数量。支持固定补货数量；需要校验活动库存限制。
无库存兜底平台库存低于阈值且系统无可用库存时，补到配置的兜底数量。存在本地无货但平台可售风险，必须记录规则和执行日志。

后台任务仅读取“库存同步 = 开启”的 SKU 规则。关闭开关后不删除规则参数，重新开启时继续使用原配置。

13. 接口对接

接口用途调用时机
global.seller.relation.query获取商家账号列表，识别 business_type = ONE_STOP_SERVICE 的全托管店铺。店铺关系同步。
aliexpress.choice.products.list按店铺分页获取商品列表，固定传 version = 2，保存完整返回数据。商品列表全量和增量同步。
aliexpress.choice.product.query按店铺和 item_id 获取商品及 SKU 详情，固定传 version = 2。新增商品、商品变化或状态复核时。
aliexpress.choice.product.stocks.query查询 SKU 各平台仓库的实时库存。库存展示、写入前校验、写入后回查。
aliexpress.choice.product.stocks.update更新 SKU 对应平台仓库库存。用户保存库存或后台规则触发时。

13.1 下架判断

  1. 优先读取 aliexpress.choice.products.list 返回商品记录中的 product_status。
  2. product_status 命中平台下架、删除或失效枚举时，ERP 主状态更新为已下架。
  3. 单次列表未返回 item_id 时，调用 aliexpress.choice.product.query 复核，不能直接判定下架。
  4. 平台原始状态枚举必须完整保存，并映射为 ERP 标准状态。
枚举校准：product_status 的具体原始枚举值以速卖通官方文档和真实 version=2 返回 JSON 为准，开发前必须建立并评审映射表。

14. 后台库存同步流程

  1. 扫描库存同步开关为开启的 SKU 规则。
  2. 校验店铺授权、Listing、SKU、本地 SKU 映射和平台仓库映射。
  3. 调用库存查询接口获取 SKU 各平台仓库实时库存。
  4. 读取本地 SKU 可用库存。
  5. 按补货方式和仓库维度计算目标库存。
  6. 校验触发阈值、活动库存保护及平台禁止降库存规则。
  7. 仅对需要变化的 SKU + 仓库调用库存更新接口。
  8. 解析 SKU + 仓库级结果，不能只判断接口顶层 success。
  9. 更新成功后再次查询平台库存，保存库存快照并记录日志。

15. 数据与日志要求

数据类别必需字段
Listing 标识channel、channel_seller_id、item_id。
SKU 标识item_id、sku_id / 在线 SKU、本地 SKU、SKU 编码、货品条码、货品 ID。
仓库标识sku_id、warehouse_code、warehouse_name。
库存快照old_platform_qty、current_platform_qty、local_available_qty、target_qty。
同步规则sync_enabled、rule_type、threshold_qty、replenish_qty、fallback_qty。
接口日志request_payload、response_payload、error_code、error_message、task_id。
审计字段operator、created_at、updated_at、source_api。

16. 验收标准

  1. 仅同步并展示 business_type = ONE_STOP_SERVICE 的全托管店铺。
  2. 状态 Tab 仅包含全部、销售中、审核中、审核不通过、已下架，主状态统计互斥且加总等于全部。
  3. 商品列表默认每页 100 条，支持切换 50、100、200、500 条/页。
  4. 列表不展示最近变化列；操作列仅保留日志。
  5. 点击商品 SKU 数量入口打开右侧宽抽屉，展示该 Listing 下全部 SKU。
  6. SKU 抽屉字段完整、表头吸顶、货品 ID 不截断，每个 SKU 展示对应图片。
  7. 多仓库存按 SKU + 仓库独立展示、修改、保存和回查。
  8. 活动 Listing 展示 SALE 标签；活动 SKU 各仓库存不得降低。
  9. 库存同步弹窗支持映射关系、同步状态和补货方式筛选。
  10. 每条 SKU 有独立库存同步开关；关闭后后台任务不执行，但保留规则配置。
  11. 支持逐条配置与勾选 SKU 后批量修改补货方式，批量操作不影响未选数据。
  12. 操作日志支持时间范围、操作模块、操作人筛选及分页。
  13. 所有库存更新均保存请求、响应、更新前后库存及操作日志。

17. 本期确认结论

  • Listing 主列表不展开 SKU，避免十万级铺货场景下的数据量和页面性能问题。
  • SKU 使用右侧宽抽屉集中展示和维护。
  • 售罄、货品未绑定不作为状态 Tab，仅作为筛选和汇总特征。
  • 商品详情页和原始 JSON 入口取消。
  • 库存同步开关、补货方式和补货逻辑均按 SKU 粒度配置。
  • 全托管多仓库存按仓库独立维护，活动库存限制按 SKU + 仓库校验。
